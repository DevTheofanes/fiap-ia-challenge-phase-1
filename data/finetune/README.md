# Fine-Tuning Dataset — Provenance & Schema

## Overview

This directory contains instruction-tuning pairs for oncology LLM fine-tuning, produced by `scripts/prepare_finetune_data.py`.

Important: the repository uses public and synthetic data to simulate the challenge requirement for internal hospital medical data. It does not contain real hospital PHI.

## Files

| File | Description |
|------|-------------|
| `train.jsonl` | Training split (80% by default) |
| `val.jsonl` | Validation split (20% by default) |
| `*_raw.jsonl` | Optional user-provided raw datasets (not committed) |

## Schema

Each line is a JSON object with two fields:

```json
{"prompt": "<anonymized question>", "completion": "<anonymized answer>"}
```

Compatible with `trl.SFTTrainer` and any Hugging Face fine-tuning pipeline that expects prompt/completion pairs.

## Data Sources

1. **MedQuAD (primary)** — Public-domain medical Q&A from the `abachaa/MedQuAD` repository. For M1 we use the `1_CancerGov_QA` XML subset and filter it for oncology relevance.

2. **PubMedQA (optional)** — MIT-licensed `ori_pqal.json`, loaded with `--pubmedqa-file`.

3. **Synthetic (fallback only)** — Generated by Gemini via `src/llm/prompts.py::format_synthetic_qa_prompt` when the public sources do not provide enough rows.

4. **User-provided (optional)** — Pass `--input-file` to the script. Rows are filtered by oncology keywords before inclusion (see below).

## Oncology Keyword Filter

User-provided rows must contain at least one of the following (case-insensitive) in the combined question+answer text:

`cancer`, `tumor`, `carcinoma`, `biopsy`, `malignant`, `malignancy`, `oncology`, `breast`, `mammogram`, `metastasis`, `chemotherapy`, `radiation`, `staging`, `prognosis`, `pathology`, `biomarker`, `her2`, `estrogen`, `progesterone`, `lumpectomy`, `mastectomy`, `lymph node`, `benign`, `lesion`, `adenocarcinoma`, `sarcoma`

## Anonymization

The following categories are redacted before writing:

| Category | Replacement |
|----------|-------------|
| ISO/US/written dates | `[DATE]` |
| Age expressions | `[AGE]` |
| Patient IDs / MRN | `[PATIENT_ID]` |
| 5+ digit numbers | `[NUM]` |
| Doctor names (`Dr. X`) | `Dr. [NAME]` |
| Patient names after "patient" | `[NAME]` |
| Institution names | `[INSTITUTION]` |
| Phone numbers | `[PHONE]` |
| Email addresses | `[EMAIL]` |

## Split Parameters

- Default total: 625 pairs
- Default val split: 20%
- Default seed: 42 (`config.RANDOM_STATE`)
- Deduplication: by lowercased question text
- M1 guardrail: the script fails unless the final split leaves at least 500 rows in `train.jsonl`

## Regeneration

```bash
# Activate the project environment first
python3 -m venv .venv && source .venv/bin/activate

# Download MedQuAD once
git clone --depth 1 https://github.com/abachaa/MedQuAD.git /tmp/MedQuAD

# Public data only: MedQuAD CancerGov + PubMedQA
python scripts/prepare_finetune_data.py \
    --medquad-dir /tmp/MedQuAD/1_CancerGov_QA \
    --pubmedqa-file pubmedqa-master/data/ori_pqal.json \
    --seed 42

# PubMedQA only with synthetic fallback
python scripts/prepare_finetune_data.py \
    --pubmedqa-file pubmedqa-master/data/ori_pqal.json \
    --total 625 --seed 42

# Synthetic fallback if public data is not enough
# Requires GEMINI_API_KEY or LLM_USE_MOCK=true
python scripts/prepare_finetune_data.py --total 625 --seed 42
```
